# Runtime budget skipped re-critique and render attempts

**Date:** 2026-09-26 00:32
**Files:** backend/app/operation_trace.py, backend/app/ai_agents/revision_loop.py, backend/app/services/neural_audio_render.py, backend/app/services/neural_audio_stems.py, docs/observability.md
**Severity:** medium

## Problem

`OPERATION_MAX_RUNTIME_MS` stopped the next spine agent, the next revise agent, and the next model call. A re-critique Critic still started after that wall, and a neural render or stem-set attempt with the same run id still called the engine.

## Root Cause

The wall check was added only at the call sites that existed when the loop was first wired: before each spine agent, before each revise agent, and inside `reserve_model_call`. The re-critique Critic is a later call in the same pass, and it was left off that list. Render attempts run on a worker that cannot see the request context, so they only consulted cancel state and the attempt cap. The run's start time was discarded when the span closed.

## Solution

- Record a process-wide run clock (start time and wall limit, max 256) when a run span opens. A request `max_wall_ms` can only lower that limit.
- `render_attempt_decision` returns `runtime` when that clock is past the wall. The render and stem runners store `failed` / `operation_runtime_budget` and do not call the engine.
- The revision loop calls the same budget check before the re-critique Critic and keeps the last valid candidate.

## Prevention

- When a budget is specified as "before the next child," name every child kind in one decision helper and call that helper at each start site, including the last step of a loop.
- Workers that do not share the request context need a process-wide clock, not only the open span.
- Cover the stop with a test that counts the next child. An earlier stop in the same loop can hide a missing check.
