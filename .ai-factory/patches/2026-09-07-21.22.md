# Persist fingerprint missed metadata-only Save skips

**Date:** 2026-09-07 21:22
**Files:** frontend/src/utils/projectPersistRevision.js, frontend/src/utils/projectPersistRevision.test.js, frontend/src/store/musicStore.js, frontend/src/store/musicStore.project.test.js, frontend/src/components/ProjectComposerBar.jsx, frontend/src/components/ProjectBrowser.jsx
**Severity:** high

## Problem

Clicking composer Save often produced no Network `PATCH /projects/:id`. Metadata-only edits (key, harmony, sections, track name/instrument, generationMeta) stayed in memory and disappeared on reload.

## Root Cause

Dirty detection compared `compositionRevisionKey()` (playback subset: tempo, ticks, events, track id/volume) to `lastSavedRevision`. Fields the PATCH API persists but playback ignores never changed that key, so `markProjectDirty` treated the project as clean, cancelled autosave, and `saveCurrentProject` early-returned without HTTP. Manual Save used `reason: 'manual'`, which still hit that gate, with no user-visible feedback.

## Solution

- Added `projectPersistRevisionKey(composition, generationMeta)` covering full persistable composition fields plus generation meta.
- Drove dirty / autosave / hydrate / rename cleanliness off `lastSavedPersistRevision`.
- Kept `compositionRevisionKey` for playback scheduling only.
- Manual / `manual-force` Save always PATCHes when a project is open; autosave remains fingerprint-gated.
- Composer bar uses `manual-force`; `[FIX]` logs cover skip/start/success/fail without full prompts or composition dumps.
- ProjectBrowser rename confirm label: Save → Rename.

## Prevention

- Never reuse playback/revision hashes for persistence dirty checks when the persisted payload is wider than the audible subset.
- Manual Save should force a flush (or show explicit “already saved”); silent no-op looks like a dead button.
- Unit-test metadata-only and generationMeta-only dirty → PATCH paths alongside note-edit autosave.
