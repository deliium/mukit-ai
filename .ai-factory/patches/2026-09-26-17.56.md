# Completion codes were recorded without being checked

**Date:** 2026-09-26 17:56
**Files:** backend/app/services/autonomous_constraints.py, backend/app/services/autonomous_composer.py, backend/tests/test_autonomous_constraints.py, .ai-factory/DESCRIPTION.md
**Severity:** medium

## Problem

`project_plan_valid`, `harmony_plan_key`, `motif_plan_present`, and `critique_stored` were written onto the stage after the worker returned. `assert_stage_completion` treated those codes as deferred, so a plan that dropped a stage, a harmony key that was not the opening key, a motif that missed the theme section, or a critique that was not `agent.critique.v1` could still be marked completed.

## Root Cause

The scheduler stamped the code from a fixed map. The checker only implemented score-writing codes and then logged the rest as deferred. The assumption was that the fake agents always emit a conforming plan, so the stamp and the check were the same thing.

## Solution

`assert_stage_completion` now validates those four codes. The scheduler calls it after the worker returns and before the stage is marked completed. A passing plan stage replaces the in-memory project plan with the validated payload. Failures stay `autonomous_constraint_failed` and do not include note text. `.ai-factory/DESCRIPTION.md` now lists the autonomous composer.

## Prevention

When a closed completion code is added to the stage graph, add the predicate to `assert_stage_completion` in the same change and cover a failing payload in `tests/test_autonomous_constraints.py`. Do not mark a stage completed from a string that the checker does not evaluate.
