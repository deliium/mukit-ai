# Assemble failed when LLM events overflowed duration

**Date:** 2026-09-07 12:43
**Files:** backend/app/services/llm_music_generator.py, backend/tests/test_llm_staged_composer.py
**Severity:** high

## Problem

Staged generation completed all compose stages, then assemble failed with
`Track events must fit within the composition duration`. Soft-fail diagnostics
routed repair back to `assemble_composition`, which re-ran the same drafts and
exhausted the repair budget (HTTP 502).

## Root Cause

Draft notes are not duration-bounded against form length. Assemble copied LLM
`start_tick`/`duration_ticks` as-is into canonical `NoteEvent`s, so notes that
ended past `bar_count * bar_ticks` failed `Composition` validation. Duration
failures have no track index in the pydantic `loc`, so
`_infer_assemble_failed_stage` fell through to `assemble_composition`. Integrity
codes `event_out_of_range` / `bar_overflow` were also mapped to assemble, a
non-LLM node that cannot rewrite notes.

## Solution

1. Clamp draft events at assemble: truncate notes that cross the end, drop notes
   that start at/after the end, and log with
   `[FIX] Clamped assemble events to composition duration`.
2. When duration validation still fails, infer the owning compose stage by
   scanning overflowing drafts.
3. Route integrity `event_out_of_range` / `bar_overflow` (and preserved
   `schema_invalid.failed_stage`) to compose stages instead of assemble.
4. Tests: slight overflow succeeds after clamp; past-end-only melody remains
   `InvalidLLMOutputError` via empty-track integrity (not provider failure).

## Prevention

- Treat duration fit as an assemble merge concern: clamp before constructing
  `Composition`, same pattern as unique track-ID remapping.
- Never route content/bounds repair targets to non-LLM `assemble_composition`.
- Cover both clampable overflow and drop-to-empty required-track cases in staged
  composer tests.
