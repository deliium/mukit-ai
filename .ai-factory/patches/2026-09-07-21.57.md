# Composer prompt edits not persisted or restored

**Date:** 2026-09-07 21:57
**Files:** frontend/src/store/musicStore.js, frontend/src/store/musicStore.project.test.js
**Severity:** high

## Problem

Changing mood/genre (and other Generate form fields) then clicking Save returned HTTP 200, but after reload the form showed the old values. `generation_prompt` in the project payload did not reflect the edited form.

## Root Cause

Two gaps in the save/hydrate loop:

1. **Save used stale `generationMeta.prompt`** frozen at last `completeGeneration`. `updatePrompt` only mutated live `prompt` state and never synced `generationMeta`, so PATCH rewrote the previous snapshot.
2. **Open/hydrate never restored the form** from `generation_prompt` — only `generationMeta` was set — so even a correctly stored prompt would not appear in Genre/Mood inputs after reload.

## Solution

- `updatePrompt` syncs `generationMeta` from `buildPromptSnapshot(prompt)` and marks the project dirty when a project is open.
- `saveCurrentProject` always builds `generation.prompt` from the live form (source of truth).
- `hydrateProject` maps `generation_prompt` back into composer `prompt` fields (arrays → comma strings) and normalizes `generationMeta` for stable fingerprints.
- Added `[FIX]` logs for sync/hydrate/save genre+mood (no full prompt dump).
- Tests cover prompt dirty→PATCH and open restore of mood/genre/instruments/sections.

## Prevention

- Treat the Generate form as the editable source of truth for persisted `generation_prompt`; never save a snapshot that is not updated on form edits.
- On project open, always hydrate UI state from every persisted field the user can edit.
- Regression tests: edit mood/genre → Save payload; open project → form equals stored prompt.
