# Bass part MusicXML omitted clef (OSMD defaulted to treble)

**Date:** 2026-09-07 15:46
**Files:** backend/app/services/music_json_renderer.py, backend/tests/test_music_json_renderer.py
**Severity:** medium

## Problem

Dedicated bass parts in the notation tab rendered with a treble (G) clef
instead of bass (F). OSMD showed the wrong staff layout for bass tracks.
MusicXML for non-piano parts contained no `<clef>` element at all.

## Root Cause

`_render_canonical_musicxml` and `_render_legacy_musicxml` inserted key,
meter, and tempo on measure 1 for single-staff (non-piano) parts but never
inserted a clef. Piano grand-staff paths already called `TrebleClef()` /
`BassClef()`; OSMD therefore defaulted missing clefs to treble for bass
instruments and `role: "bass"` tracks.

## Solution

Added `_uses_bass_clef` / `_clef_for_composition_track` /
`_clef_for_legacy_track` that choose `BassClef` when `staff == "bass"`,
`role == "bass"`, or `"bass"` is in the instrument name, otherwise
`TrebleClef`. Insert the chosen clef on measure 1 for every non-piano
part. Log with `[FIX]` prefix (track id/role/instrument/clef only — no
raw MusicXML). Tests assert F for bass, G for melody, and G+F for piano
grand staff.

## Prevention

- When adding MusicXML staff metadata, always set an explicit clef for
  every part (do not rely on OSMD/music21 defaults).
- Mirror clef policy between canonical and legacy render paths.
- Add renderer assertions for `<sign>F</sign>` / `<sign>G</sign>` whenever
  track role or staff semantics change.
