# Personal composer torch path was layered and stubbed

**Date:** 2026-10-02 19:30
**Files:** backend/app/services/collaboration_access.py, backend/app/services/personal_composer_service.py, backend/app/personal_composer/lora.py, backend/app/personal_composer/trainer.py, backend/app/music_transformer/inference.py, backend/app/services/symbolic_composition_generate.py
**Severity:** high

## Problem

`personal_composer_service` imported `enforce_current` from the FastAPI collaboration router. A completed torch adapter raised instead of sampling, and torch eval stored loss and token accuracy as `0.0`.

## Root Cause

The owner check was copied from the HTTP guard, which wraps `CollaborationError` as `HTTPException`, so the service depended on a router. Torch generate and eval were left as placeholders that did not load `adapter.pt` or run a forward pass.

## Solution

`authorize_current` lives in the collaboration service and raises `CollaborationError`. The router still maps that error to HTTP 403. Torch generate loads the frozen base plus saved LoRA tensors and calls `sample_and_decode`. Eval runs a no-grad next-token cross-entropy and argmax accuracy on the snapshot token rows.

## Prevention

- Services authorize through `collaboration_access`, not `app.routers`.
- A torch adapter test must assert loss is greater than zero and that sample-and-decode returns `composition.v2`.
- Do not record a constant metric when the function did not run a forward pass.
