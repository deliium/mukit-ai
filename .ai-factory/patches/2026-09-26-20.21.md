# Persistence doc omitted the stage-branch route

**Date:** 2026-09-26 20:21
**Files:** docs/project-persistence.md, backend/tests/test_autonomous_persistence_docs.py, backend/tests/test_autonomous_composer_control.py
**Severity:** low

## Problem

The autonomous-composer paragraph in `docs/project-persistence.md` described the shared history graph and arrangement reject, but not that branching from a stage uses `POST /projects/{id}/branches` and leaves `autonomous_runs.branch_id` unchanged.

## Root Cause

The docs task named two facts in one parenthetical (existing branch route, run does not move). The written paragraph covered reject and restore, which are the other history reuse, and treated the branch sentence as already covered by `docs/autonomous-composer.md`.

## Solution

The same paragraph now states that branching from a stage calls `POST /projects/{id}/branches`, does not check out, and does not change the run’s `branch_id`. A docs test locks those phrases. The history test asserts the new branch id is not `autonomous_runs.branch_id`. No runtime path changed, so no `[FIX]` log was added.

## Prevention

When a plan task names the sentence a specific doc page must contain, verify that page after the edit, not only the feature doc that already mentions the route.
