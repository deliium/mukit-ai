# Remap post-stream KeyError away from provider failure

**Date:** 2026-09-15 00:35
**Files:** backend/app/services/llm_music_generator.py, backend/tests/test_llm_staged_composer.py
**Severity:** high

## Problem

Staged DeepSeek generation completed most stages (including a streamed accompaniment repair), then returned HTTP 502:

`LLM provider request failed: KeyError`

Logs showed `[FIX] Streamed LLM chat completion` immediately followed by `LLM provider/API failure` with no `Composer stage validation failed` / `Resolved accompaniment drafts` lines — so the failure was local after the provider returned, not a DeepSeek outage.

## Root Cause

1. `_run_json_stage` caught JSON/schema parse errors but not `KeyError` from `on_success` (e.g. accompaniment post-processing).
2. `generate_music_json`’s broad `except Exception` labeled any leftover local error as “LLM provider/API failure” and exposed only `type(exc).__name__`, hiding the missing key.

## Solution

- Treat `KeyError` / `AttributeError` (with other local parse errors) inside `_run_json_stage` as `InvalidLLMOutputError`, including `repr(exc)` and stage name.
- Remap unexpected local `KeyError` / `AttributeError` / `TypeError` / `ValueError` at the outer generator boundary the same way (with `exc_info=True`), instead of provider failure.
- Harden accompaniment `on_success` payload access (`.get("tracks")` + skipped list check).
- Regression: `test_accompaniment_post_stream_keyerror_is_not_provider_failure`.

## Prevention

- Never map bare `Exception` to “provider failure” without excluding local parse/state errors.
- Include `repr(exc)` (and stack) when remapping so missing keys are visible even when the log format omits `extra` fields.
- Keep stage `on_success` inside the same try/except as JSON parse.
