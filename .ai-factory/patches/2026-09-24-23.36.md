# Add mix-analysis synthetic WAV fixture coverage

**Date:** 2026-09-24 23:36
**Files:** backend/tests/fixtures/audio/mix_analysis/*, backend/tests/test_mix_analysis.py, docs/testing.md
**Severity:** low

## Problem

`/aif-verify` reported thinner Task 9 DSP fixture breadth: plan called for
`backend/tests/fixtures/audio/mix_analysis/` with hot-peak / clipped / stereo /
two-stem overlap WAVs, but tests only used inline `_write_wav` for a hot peak
and fake-mode API coverage.

## Root Cause

Implementation preferred ephemeral tmp WAVs for speed; the dedicated fixture
directory and clipped/stereo/masking scenarios were deferred during the
initial test pass.

## Solution

- Added stdlib builders + committed short PCM16 fixtures under
  `tests/fixtures/audio/mix_analysis/`.
- Added DSP unit tests that measure fixtures with `MIX_ANALYSIS_FAKE_MODE=0`,
  assert observation codes (clipping, stereo_imbalance, spectral_masking_proxy),
  and confirm WAV bytes unchanged after measure.
- Documented fixture rebuild path in `docs/testing.md`.

## Prevention

When a plan lists a fixtures directory + named WAV scenarios, ship the
directory and at least one stdlib (non-fake) assertion per scenario in the
same test task — do not rely solely on fake-mode API journeys.
