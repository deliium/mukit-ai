# Clear stale Network Error banner after healthy API rediscovery

**Date:** 2026-09-14 23:15
**Files:** frontend/src/App.jsx, frontend/src/api/musicApi.js, frontend/src/api/projectApi.js, frontend/src/store/musicStore.js, frontend/vite.config.js
**Severity:** medium

## Problem

UI showed bare `Network Error` while backend logs reported `200` for `/health`, `/projects`, and `/llm/models`.

## Root Cause

Axios surfaces aborted/disconnected generate calls as `Network Error`. That string was stored in `uiError` and kept on screen after later requests succeeded, because successful health/model discovery and project-list loads never cleared `uiError`.

Separately, Vite `http-proxy`'s `timeout` option applies to the *incoming* browser socket; pairing it with `proxyTimeout` risked odd idle aborts. Only `proxyTimeout` is appropriate for long LLM waits.

## Solution

- Clear `uiError` when App health/model discovery succeeds and when the project list loads successfully.
- Expand bare axios network failures into an actionable message (no response / proxy / abort).
- Keep Vite LLM proxy `proxyTimeout: 300000` only; drop incoming `timeout`.

## Prevention

- Any path that sets `apiStatus: 'healthy'` or completes a successful bootstrap fetch should clear stale global `uiError`.
- Prefer `proxyTimeout` (upstream) over `timeout` (incoming socket) for long Vite-proxied LLM routes.
