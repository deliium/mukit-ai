# Continuation settings and the quiet ahead-note queue were undocumented

**Date:** 2026-09-29 21:42
**Files:** .env.example, docs/adaptive-runtime-continuation.md, frontend/src/components/AdaptiveContinuationPanel.jsx, frontend/src/store/musicStore.js
**Severity:** low

## Problem

`ADAPTIVE_CONTINUATION_*` caps were loaded from the environment, but `.env.example` only listed the adaptive-score document caps. The Fill-ahead queue recorded ticks with an empty Tone callback, and that silence was not written down, so a reader could expect the buffer notes to sound.

## Root Cause

The implementation plan treated the seven caps as code defaults and treated scheduling as “place the tick on a private queue.” The docs step named three of the caps and the audible flag, and it stopped before saying the callback does not attack a synth.

## Solution

Listed all seven settings, with defaults and accepted ranges, in `.env.example` and in `docs/adaptive-runtime-continuation.md`. The same doc, and a short comment at each `scheduleContinuationAt` call, states that the callback records the ahead tick and does not attack a synth. The published playback loop keeps sounding.

## Prevention

- When a feature adds env caps, add the same names to `.env.example` in the same change as the settings module.
- When a scheduler records time without playing a note, say that in the feature doc next to the audible flag.
