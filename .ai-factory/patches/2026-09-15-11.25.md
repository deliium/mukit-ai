# Genre/mood not persisted on project Save

**Date:** 2026-09-15 11:25
**Files:** frontend/src/store/musicStore.js, frontend/src/store/musicStore.project.test.js
**Severity:** medium

## Problem

Editing Genre or Mood in the composer form and clicking Save did not persist those values. After reopening the project, the fields reverted to defaults or prior DB values.

## Root Cause

Two coupled issues in the project save path:

1. `syncGenerationMetaFromPrompt` returned early when `generationMeta` was null (imported or never-generated projects). Prompt edits never entered the persist fingerprint, so Save often skipped generation payload entirely.

2. When `generationMeta` was null, `saveCurrentProject` sent `clear_generation: true` on composition saves, which could wipe stored prompt metadata instead of leaving it untouched.

## Solution

- Upsert `generationMeta` from the live prompt whenever the user edits prompt fields on an open project (provider/model remain null until a real generation apply).
- Stop sending `clear_generation` on routine saves; only PATCH `generation` when `generationMeta` exists after prompt sync.
- Extended unit tests for prompt-only persistence on projects without prior generation metadata.

## Prevention

- Treat composer prompt fields as persistable project metadata independent of LLM apply provenance.
- When adding new form fields to the generation prompt, verify they flow through `buildPromptSnapshot`, `syncGenerationMetaFromPrompt`, and `saveCurrentProject`.
- Add regression tests whenever save payload gating changes.
