# Patch: Variable-meter V2 client validation

## Problem
Imported MIDI with `time_signature_changes` failed frontend install: `duration_ticks must match bar_count and time_signature.` Playwright import journey could not complete.

## Root Cause
`musicJsonValidation.js` assumed constant root meter (`duration_ticks === bar_count * root_bar_ticks`) and checked meter/key change ticks with `tick % rootBarTicks`. Backend `compile_timeline` correctly sums variable bar lengths (e.g. 4/4 + 3/4 → 3360).

## Solution
- Validate V2 duration via `compileTimeline` from `compositionTimeline.js`
- Validate section spans against compiled bar boundaries
- Require meter/key change ticks to land on compiled bar starts
- Keep single-meter V1 checks unchanged
- Mark roadmap milestone **MIDI and MusicXML import** complete

## Prevention
When frontend mirrors V2 timeline invariants, reuse `compileTimeline` / bar boundaries instead of root-meter arithmetic whenever `time_signature_changes` may be present. Add regression fixtures that include mixed meters (import multitrack shape + `timeline_mixed_meter_tempo.json`).
