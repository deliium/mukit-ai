# Fake V2 region edit failed integrity density on short compositions

**Date:** 2026-09-08 18:33
**Files:** backend/app/services/fake_llm.py, backend/app/services/llm_composition_editor.py, backend/tests/test_llm_fake_provider.py, frontend/src/utils/tonePlaybackEngine.js, frontend/e2e/helpers.js, frontend/e2e/v2-user-journey.spec.js
**Severity:** high

## Problem

V2 Playwright journey logged `/llm/edit-composition-region` **500** on the 4-bar expressive fixture (bars 1–2 melody). The journey still “passed” because it only waited for existing note counts. Tone also logged `cancelAndHoldAtTime: null` on bass MonoSynth releases.

## Root Cause

Fake region patches emitted **one note per selected bar**. After replacing bars 1–2 of a 4-bar piece, melody had 3 events total vs integrity `min_events=4` (`empty_required_track` / too sparse). `CompositionRegionPatchError` bubbled uncaught from the fake edit path → FastAPI **500**.

Separately, `scheduleRelease` always called `triggerRelease(pitch, time)`. MonoSynth expects `triggerRelease(time)`; the pitch string became an invalid time and Tone’s envelope path hit `cancelAndHoldAtTime(null)`.

## Solution

- Fake patch planner sizes in-region notes from `_min_events_for_track` minus preserved outside events (`[FIX:fake-region-density]`).
- Map leftover `CompositionRegionPatchError` from fake edit to `InvalidLLMOutputError` (`[FIX:fake-region-edit]`) so routes return 502 instead of 500.
- Mono vs Poly release dispatch + invalid-time guard (`[FIX:tone-release]`).
- E2E `waitForAiEditSuccess` asserts `aiEditStatus === 'success'` (`[FIX:e2e-ai-edit]`).
- Regression: `test_fake_region_edit_preserves_integrity_on_v2_expressive`.

## Prevention

- Deterministic fake patches must satisfy the same integrity gates as real apply paths, especially density on short compositions.
- Never treat “notes still present” as proof an AI edit succeeded — assert edit status/outcome.
- Tone release APIs differ by synth class; do not pass note names to MonoSynth/MembraneSynth `triggerRelease`.
