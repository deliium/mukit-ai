# Film score review fields and preview scoring revision

**Date:** 2026-10-01 16:24
**Files:** frontend/src/components/FilmScorePanel.jsx, frontend/src/utils/filmScorePlan.js, frontend/src/store/musicStore.js, frontend/src/utils/filmScorePlan.test.js, docs/film-scoring.md
**Severity:** medium

## Problem

The Agents tab preview omitted the locked review inputs: profile id, profile strength, motif checkboxes, and target duration. The summary omitted the section label and whether a hit added a tempo change. Commit sent `pictureScoring.document_revision`, or a fresh scoring GET, instead of `preview.plan.scoring_document_revision`.

## Root Cause

The first panel followed the shorter task checklist (brief, instruments, summary bars, hit status) and treated the picture document as the scoring CAS source. The locked UI list and the commit rule both name the preview plan as the source of those fields. A later picture-tab save could therefore commit a candidate against a different scoring revision than the one the plan was compiled from.

## Solution

`filmScoreRequestBody` builds the preview payload from those fields and rejects a non-positive duration before the request. `scoringRevisionForCommit` reads only `plan.scoring_document_revision`. The panel summary prints the section label and a tempo-change mark. `[FIX]` logs record counts and the revision, not the brief.

## Prevention

When a plan locks both a task checklist and a UI field list, review the field list before calling the panel done. Commit CAS values that the preview already returned should be taken from that preview, not from a sibling document that can move.
