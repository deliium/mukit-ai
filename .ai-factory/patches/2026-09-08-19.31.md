# Close verify soft warnings for V2 rules context

**Date:** 2026-09-08 19:31
**Files:** .ai-factory/RULES.md, .ai-factory/rules/base.md, AGENTS.md
**Severity:** low

## Problem

`$aif-verify` on composition-v2 completed with **warn**: missing `.ai-factory/RULES.md`, and `rules/base.md` still described docs as composition.v1-only. Local WAV export 503 without SoundFont remained a soft e2e console error (already documented; not a code defect).

## Root Cause

V2 docs and AGENTS were updated during the feature, but the AI Factory axioms file (`paths.rules_file`) was never created, and the auto-detected `rules/base.md` docs bullet was not refreshed when V2 became canonical.

## Solution

- Added `.ai-factory/RULES.md` with short axioms: events-only playable source, V1 input-only, routers/services preference, secret/payload log hygiene, shell decomposition, `LOG_LEVEL` control.
- Updated `rules/base.md` docs line to cite composition.v2 (canonical) + v1 (compat) and `RULES.md`.
- Pointed `AGENTS.md` AI Context / e2e lines at `RULES.md` and V1/V2 Playwright journeys.
- Left local missing-SoundFont WAV 503 unchanged; operators use Docker/`COMPOSITION_WAV_SOUNDFONT` / `fluid-soundfont-gm` as documented in `docs/composition-v2.md` and `docs/testing.md`.

## Prevention

- When canonical schema version changes, refresh `RULES.md`, `rules/base.md`, and `AGENTS.md` in the same docs checkpoint as `docs/composition-v*.md`.
- Treat missing `paths.rules_file` as a verify soft warning that should be closed before `/aif-commit`, not deferred indefinitely.
- Do not treat local WAV SoftFont absence as a product bug when routes correctly return `503` and docs already describe the requirement.
