# Stream LLM completions and align stream_chunk_timeout

**Date:** 2026-09-15 00:21
**Files:** backend/app/services/llm_chat_client.py, backend/app/services/llm_music_generator.py, backend/app/services/llm_composition_editor.py, backend/app/services/llm_motif_editor.py, backend/tests/test_llm_chat_client.py
**Severity:** high

## Problem

After raising the HTTP timeout to 180s and disabling LangChain TCP keepalive, DeepSeek `plan_form` still failed around 120–180s:

1. Non-streaming: `APIConnectionError` / `incomplete chunked read` (~122s)
2. Streaming with default LangChain settings: `StreamChunkTimeoutError` at 120s (default `stream_chunk_timeout`)
3. Streaming with `stream_chunk_timeout=180`: still no content chunks; DeepSeek completions currently hang (curl to `/chat/completions` times out with 0 bytes while `GET https://api.deepseek.com/` returns quickly)

## Root Cause

Multiple stacked limits:

- Non-streaming bodies can be closed mid-chunk by the provider/gateway on long generations.
- LangChain’s default `stream_chunk_timeout` is 120s and aborts before our 180s HTTP timeout.
- Independently, DeepSeek’s chat-completions endpoint can accept/connect yet emit no body bytes for long periods (provider-side stall), which no client timeout can “fix” into a successful completion.

## Solution

- Add `ainvoke_chat_text()` that streams via `astream`, concatenates chunks, and retries once on transport/incomplete-body / stream-chunk timeouts.
- Build ChatOpenAI with `streaming=True`, `http_socket_options=()`, `max_retries=0`, and `stream_chunk_timeout=timeout_seconds`.
- Wire generation / region-edit / motif chat invokes through the streaming helper.

## Prevention

- Prefer streaming for long JSON stages against OpenAI-compatible providers.
- Keep `stream_chunk_timeout` aligned with `LLM_REQUEST_TIMEOUT_SECONDS`.
- When diagnosing hangs: probe `GET https://api.deepseek.com/` (reachable) vs `POST /chat/completions` (may stall); distinguish app timeout config from provider outage.
