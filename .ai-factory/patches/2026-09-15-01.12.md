# Coerce incomplete plan_themes sequence deployments

**Date:** 2026-09-15 01:12
**Files:** backend/app/services/llm_music_generator.py, backend/tests/test_llm_staged_composer.py
**Severity:** high

## Problem

`plan_themes` failed after a successful DeepSeek stream with:

`ValidationError: ... sequence requires steps, interval, and step_ticks`

Stage retries exhausted → HTTP 502. The model emitted a `sequence` deployment without the required parameter trio.

## Root Cause

`ComposerThemeDeployment` correctly requires `sequence_steps`, `sequence_interval_semitones`, and `sequence_step_ticks`, but `_parse_theme_plan` validated raw LLM JSON with no coercion. The theme prompt listed `sequence` as allowed without showing the required parameter shape.

## Solution

- Add `_coerce_theme_plan_payload` before validation: strip mechanical `variation_strength`, default missing transpose/time-scale knobs, and demote incomplete `sequence` deployments to `repeat` (avoids overflow from aggressive defaults).
- Extend the theme prompt with a concrete sequence example and explicit required-parameter rules.
- Unit test covers incomplete sequence → `repeat` coercion.

## Prevention

- Keep mechanical ops that need structured params documented in the prompt example, not only the allow-list.
- Prefer coerce-or-demote over hard stage failure for incomplete but recoverable theme plans.
