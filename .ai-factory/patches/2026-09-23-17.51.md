# ESLint: bare AbortController and unused live scheduler param

**Date:** 2026-09-23 17:51
**Files:** frontend/src/store/musicStore.js, frontend/src/utils/liveAccompanimentScheduler.js, frontend/src/api/livePerformanceApi.js, frontend/src/api/livePerformanceApi.test.js
**Severity:** low

## Problem

`/aif-verify` after co-performance implement failed ESLint (`--max-warnings 0`):

1. `musicStore.js` — `AbortController is not defined` (`no-undef`) in cold-path `requestLivePredictFill`.
2. `liveAccompanimentScheduler.js` — unused `_audioTime` in the default `onTrigger` stub (`no-unused-vars`).

## Root Cause

1. Project ESLint env does not treat bare `AbortController` as a defined global. Other store paths already used `globalThis.AbortController`; the new live predict path copied `new AbortController()` instead.
2. Underscore-prefixed unused params are still flagged — the default stub declared a second argument only for signature symmetry and never read it.

## Solution

- Extract `createLivePredictAbortController()` in `livePerformanceApi.js` (uses `globalThis.AbortController`, returns `{ ok, controller, code }` with `live_predict_no_abort` when missing).
- Wire `requestLivePredictFill` through that helper and warn + return without setting in-flight state when AbortController is unavailable.
- Drop the unused second parameter from the default scheduler `onTrigger`.
- Add unit tests covering available and missing AbortController cases.

## Prevention

- Prefer `globalThis.<WebAPI>` (or a small factory) for browser APIs in store/utils so ESLint `no-undef` stays green.
- Do not declare unused callback parameters “for documentation”; keep JSDoc on the options type instead.
- Review checklist: run `./scripts/run_tests.sh --lint-only` before claiming verify pass on FE changes.
