# AI Music Composer (Mukit AI)

## Overview

Full-stack LLM music composer that generates and edits canonical playable `composition.v2` JSON. A FastAPI backend orchestrates multi-stage LangChain/LangGraph composition, validation, secure MIDI/MusicXML import into V2, deterministic `composition.analysis.v1` musical analysis, harmony timeline editing and reharmonization preview, AI-assisted arrangement/orchestration preview, a project-scoped Adaptive Score (`adaptive.score.v1`) that references existing Composition material without storing note events, durable Composer Profiles (`composer.profile.v1`) for soft generate conditioning, explicit preference learning (`preference.choice.v1`, `docs/preference-learning.md`) that orders development and arrangement candidates and does not update a Composer Profile, optional trusted-LAN ExecutionNodes (`execution.node.v1`, `docs/execution-nodes.md`) that register with authenticated heartbeat and run typed remote `LanguageModel.complete_text` through `runtime=execution_node` without remote shell, optional capability-aware AI job scheduling (`AI_SCHEDULING_ENABLED`, `docs/ai-job-scheduling.md`) that picks a controller-local or trusted-LAN candidate when no explicit `model_id` is pinned and reschedules without silent public-cloud escalation, selective reference feature dimensions (`reference.features.v1`) plus request-scoped conditioning policy (`reference.conditioning.policy.v1`) for generate/develop/edit soft masks, MusicXML/MIDI/WAV export, and SQLite project persistence with durable revision/branch history. A React/Vite frontend provides prompt controls, import workflows, piano-roll and JSON editing, Analysis / Motifs / Harmony / Arrange / Develop / Profiles / Versions / Picture tabs, OSMD notation, and Tone.js playback of the same canonical note events. A project may also store one immutable MP4 or MOV as `video.asset.v1` with a `video.scoring.v1` sync document so the Picture tab keeps the composition cursor on that picture. Substantial AI results stay preview-first until Apply. `composition.v1` remains accepted migration/parser input.

## Core Features

- Multi-stage LLM generation of operational `composition.v2` (form → harmony → melody → bass → accompaniment → assemble → validate/repair); optional hybrid pipeline (`options.pipeline=hybrid_plan_symbolic`) where an LLM emits non-playable `composition.plan.v1` and a symbolic composer (`fake:symbolic-tiny` / Music Transformer) emits note events
- Versioned non-playable `composition.plan.v1` planning contract (form/harmony/themes/density only — never a second score)
- Secure MIDI / MusicXML / MXL import into the same V2 workspace with session import reports (no LLM required; no retained source files)
- Offline symbolic training dataset pipeline under `DATASET_ROOT` (CLI ingest/normalize/segment/split/stats; provenance-gated; never `PROJECT_DB_PATH`)
- Versioned Composition V2 tokenizer (`tokenizer.v1`) under `backend/app/tokenizer/` (CLI encode/decode/stats/viz; train+inference contract; never `PROJECT_DB_PATH` / weight load)
- Optional PyTorch Music Transformer (`music_transformer.v1`) under `backend/app/music_transformer/` (offline experiment train/eval/listen/compare over tokenizer; resume + metrics; optional generate API; never `PROJECT_DB_PATH` / GGUF in FastAPI; symbolic metrics ≠ musical quality)
- Model Lab (`model.lab.experiment.v1`, `docs/model-lab.md`) — opt-in research UI/HTTP over corpus MT experiments (`MODEL_LAB_ENABLED`); select existing dataset versions + tokenizer/architecture presets; Lab-capped train; metrics/eval/listen/compare; explicit register as `lab:{id}` on `/ai/models`; fake CI engine; never shell/argv; never writes `DATASET_ROOT` or `composition.v2` notes; no `composition.v5`; Personal Composer stays Profiles; `ai_agents/` does not import the Lab store
- Ensemble arbitration (`ensemble.arbitration.v1`, `docs/ensemble-arbitration.md`) — opt-in multi-`symbolic_composer` fan-out for one client-supplied `composition.plan.v1` + hard constraints (`ENSEMBLE_ARBITRATION_ENABLED`); hard validate before critic annotate and in-process preference rank; selection modes auto_suggest / human / top_n; session-only report until SPA `applyGenerationCandidate`; no Collab C; status not on `/ready`; never invents `composition.v5`; `ai_agents/` does not import ensemble arbitration settings
- Deterministic composition analysis (`composition.analysis.v1`) over current V2 scopes; frontend-derived cache only; optional bounded advisory context for LLM edit/repair
- Durable Composer Profiles (`composer.profile.v1`) with explicit vs derived prefs, Off/Light/Normal/Strong soft generate conditioning; prompt/hard constraints always win; never copies melodies or writes `DATASET_ROOT`. A stored preference choice does not update a Composer Profile
- Capability-aware AI job scheduling (`scheduling.policy.v1` / `scheduling.job.v1`) — when `AI_SCHEDULING_ENABLED` is on and the caller did not pin `model_id`, a pure deterministic scheduler picks a controller-local or trusted-LAN registry candidate (`prefer_local` / `fastest_available` / `memory_safe` / `fixed_node`); bounded reschedule never escalates trust to public cloud for private jobs; never writes `tracks[].events[]`. See `docs/ai-job-scheduling.md`
- Browser WebGPU inference for lightweight AI (`runtime=browser_model`, `docs/browser-webgpu-inference.md`) — SPA BrowserModelHost runs a public `symbolic.features.v1` twin on browser CPU (optional WebGPU batched cosine) with `POST /embeddings/compute` fallback; discovery-only on `GET /ai/models`; never scheduled as an ExecutionNode; never serves private host weight trees; never writes `tracks[].events[]`; no `composition.v5`
- Adaptive scores (`adaptive.score.v1`) — per-project states, variants, transitions, layers, and stingers referencing `composition.v2` sections, bar ranges, tracks, motifs, revisions, or asset ids; horizontal resequencing and vertical layering stay in the sidecar; HTTP writes never mutate the working composition; playback still comes only from `tracks[].events[]`; no `composition.v5`
- Performance conductor (`performance.plan.v1` / `performance.realization.v1`, `docs/performance-conductor.md`) — durable project plans and session realizations reinterpret one `composition.v2` expressively (rubato as tick deltas, dynamics, pedaling, balance) without rewriting pitch, harmony, or event ids; preset catalog clone only (no auto-INSERT); AI augment optional and off by default; `ai_agents/` does not import conductor modules
- Spatial music (`spatial.scene.v1` / `spatial.preview.v1`, `docs/spatial-music.md`) — durable SpatialMix layouts for tracks and/or completed neural stems; deterministic stereo + FOA ACN/SN3D compile; Web Audio / Tone preview without rewriting notes or stem WAVs; preset catalog clone only (no auto-INSERT); not Atmos; `ai_agents/` does not import spatial modules
- Ardour companion + session exchange (`ardour.companion.*.v1` / `ardour.exchange.*.v1`, `docs/ardour-companion.md`, `docs/ardour-session-exchange.md`) — optional OSC session (`ARDOUR_COMPANION_ENABLED`) with feedback-observed transport/mixer; selected MIDI region packages under `ARDOUR_EXCHANGE_ROOT` (`ARDOUR_EXCHANGE_ENABLED`); Ardour-tab ordered workflow (scope → Send → realize → Apply → prepare return); realize intents wrap arrangement/development/harmony preview engines; prepare may export SPA working `composition.v2` with preview alignment; optional SPA neural stem attach; operator Lua install script (`scripts/install_ardour_helpers.sh`); LV2 not required; never edits `.ardour` XML; never remote-executes Lua; no `composition.v5`; `ai_agents/` does not import companion or exchange modules
- Musical universe (`musical.universe.v1`) — a project group shares entities, Theme A, variants, and usage. Themes reference motif occurrences on member scores. An explicit reuse writes transformed notes into the destination `composition.v2` and records the usage. The universe document stores no pitches
- Soundtrack / production asset packs (`asset.pack.plan.v1` / `asset.pack.v1`, `docs/asset-packs.md`) — one franchise brief compiles a non-playable AssetPackPlan; explicit generate creates N independent projects (each `composition.v2`) joined to one Musical Universe, soft-conditioned by one Composer Profile (pack-side merge into each slot `creative.brief.v1`), stamped with shared `asset.pack.production.v1` targets, and optionally scaffolded with per-asset `adaptive.score.v1` state labels. Partial regenerate rewrites selected `slot_id`s only. Agents-tab Asset Pack panel never auto-generates on open. Never invents `composition.v5`; never stores note events on the pack; never writes `DATASET_ROOT`; `ai_agents/` does not import pack stores
- Derived material graph (`musical.dependency.edge.v1`) — explicit edges from motifs, themes, arrangements, variations, renders, transcriptions, and reference conditioning. An upstream change lists stale dependents and does not rewrite their notes or audio
- Content provenance (`content.provenance.record.v1`) — durable derivation DAG spanning revisions, imports, AI ops, renders, stems, and mix plans; exportable manifest with honesty that internal metadata is not cryptographic Content Credentials. Optional C2PA behind `CONTENT_CREDENTIALS_ENABLED` (default off). Soft-fail capture (unlike dependency cycle hard-fail). `ai_agents/` does not import provenance stores
- Rights governance (`rights.registry.entry.v1`, `docs/rights-governance.md`) — centralized permission-to-use registry (ownership × use policy) with pure `evaluate_rights_use`; hard-fail train/reference gates for dataset splits, personal composer, Music Transformer train, and reference analyze/condition; exportable `model.data.provenance.manifest.v1`; dataset-version `rights/` siblings (bit-stable `dataset_version_id`). Complementary to content provenance. Neural/mix render egress rights out of ship-1. `ai_agents/` does not import the rights store
- Adaptive music clients under `clients/python` (`mukit-adaptive`) and `clients/typescript` (`@mukit/adaptive-music`) call the public `/adaptive/*` session only; they do not import the studio and the studio does not import them
- Video scoring (`video.asset.v1`, `video.scoring.v1`) — one immutable MP4/MOV per project under `VIDEO_ASSET_ROOT`; a read-only ISO-BMFF probe records duration, frame rate, audio presence, and resolution; explicit frame rate, start timecode, sync origin, and spotting cues stay on the scoring document (`hit_points`); the Picture tab shares one cursor leader with Tone; a landing check compares note attacks with cue frames and does not write notes; suggestions are an explicit preview; upload, probe, settings, and playback never rewrite the stored file or `tracks[].events[]`; no `composition.v5`. `ai_agents/` does not import `video_scoring_schemas`, `video_scoring_settings`, `video_scoring_store`, `video_container_probe`, `video_scoring_map`, `video_spotting`, or `llm_video_spotting`
- Film score adaptation (`film.score.adaptation.v1`) — an explicit preview in `backend/app/services/film_score_adapt.py` chooses one local repair for a declared picture edit and leaves the rest of `composition.v2` musically identical. Commit recomputes that candidate as `film-score-adapt-apply`. Cue rows, video bytes, and the sync origin stay stored. A span that covers the whole score is refused and does not call the film-score agent. The previous timeline stays on the request. `ai_agents/` does not import `film_score_adapt`, and that module does not import `film_score_accents` or the video modules
- Selective reference features (`reference.features.v1`) — dimension masks (e.g. Rhythmic density / Orchestration texture) soft-condition generate and develop; derived reports only; never mutates the reference Composition; never copies melodies or writes `DATASET_ROOT`
- Reference conditioning policy (`reference.conditioning.policy.v1`) — explicit preserve / borrow / regenerate disposition with per-dimension strength and multi-reference assignment (e.g. texture of A + rhythm of B); wires generate, develop, and AI region edit; soft only; own-project motif reuse opt-in gated by `active_project_id`
- Explicit harmony tick-span timeline with local add/replace/remove/move/resize; `POST /harmony/reharmonize/preview` for deterministic/AI candidates (apply is client-side, fingerprint-gated)
- AI-assisted arrangement / orchestration via `GET /composition/arrangement/instruments` and `POST /composition/arrangement/preview` (ephemeral candidates; Apply commits V2 only; curated catalog not persisted as catalog IDs/ranges)
- Partial region editing via LLM patch (`replace_region`) without regenerating the full score
- Local project CRUD with SQLite persistence, debounced autosave, immutable compressed snapshots, named branches, and restore-as-child revisions. Offline copy is `python -m app.db.backup` (`backend/app/db/backup.py`, `sqlite3.Connection.backup`); it is not revision restore and has no HTTP route. Stop the backend first. Destination must not be `PROJECT_DB_PATH` or sit inside `DATASET_ROOT`
- Piano-roll and JSON editors sharing the same `editedMusicJson` Zustand state
- Browser Web MIDI / QWERTY test performance capture into a destination track (session take → one undoable V2 commit; optional quantize; never required at startup). ## Tech Stack

- **Programming language:** Python 3.14+ (backend), JavaScript (frontend)
- **Framework:** FastAPI + Uvicorn; React 18 + Vite
- **Database:** SQLite (`PROJECT_DB_PATH`) with Alembic schema migrations
- **ORM:** None — raw SQL via `sqlite3` helpers in `backend/app/db/` and `project_store`
- **LLM:** LangChain / LangGraph with OpenAI-compatible providers (OpenAI, DeepSeek) plus optional `LLM_FAKE_MODE` deterministic fixture provider for demos/E2E; optional local OpenAI-compatible sidecar (`LOCAL_LLM_*`, Compose `--profile local-ai` / `local-ai-vllm`) via `LocalLanguageModel` — app never loads weights; capability-aware `ai_runtime/` registry routes generate/edit/arrange/develop/reharmonize/motif by `AiOperation` (`GET /ai/models`, compat `/llm/models`); hybrid generation uncollapses `generate_planner` / `generate_composer` onto language vs `symbolic_composer` without silent LLM note fallback; V4 `ai_agents/` binds specialized roles to the same resolve path (`AI_AGENT_<ID>_MODEL`)
- **Music processing:** music21 (MusicXML render + import), mido (MIDI import/export), defusedxml (import preflight), FluidSynth + SoundFont (WAV)
- **Frontend libraries:** Zustand, styled-components, Tone.js, OpenSheetMusicDisplay, axios
- **Integrations:** Docker Compose production-local stack (`backend` + nginx `frontend`); optional `compose.local-ai.yml` profiles for local inference sidecars; optional `compose.neural-audio.yml` `--profile neural-audio` for MusicGen-shaped render sidecar; optional `compose.audio-recovery.yml` `--profile audio-recovery` for Demucs-shaped separation sidecar; optional LLM API keys via `.env` / Compose (backend-only); `IMPORT_*` / `AUDIO_*` / `AUDIO_RECOVERY_*` / `NEURAL_AUDIO_*` limits

## Architecture Notes

- Monolith: one API service + one SPA; logical modules (projects, import, analysis, composition/LLM, rendering/export, execution nodes) live inside `backend/app/` and `frontend/src/`
- Dependency direction: HTTP handlers → services → DB / external I/O; Pydantic schemas are shared contracts
- `composition.v2` is the operational source of truth for playable notes; `composition.v1` is migration/parser input. External imports convert directly to V2. `harmony` is explicit tick-span metadata only and must not invent audible events; raw import leaves `harmony: []`. Analysis, arrangement, development, and reharmonize previews are non-persisted until the user explicitly applies a candidate. An Adaptive Score is a separate SQLite document that points at that Composition; it does not add a second note list. A picture asset and `video.scoring.v1` are also separate from the score: markers stay on the composition, and spotting cues are `hit_points` labels with a timecode and a frame tolerance. They are not notes. A film-score adaptation preview retimes the working score for one declared picture edit and writes `tracks[].events[]` only on commit. ExecutionNodes are deployment peers (`execution.node.v1`), not a score schema; worker inference stays on the `LanguageModel` / `runtime=execution_node` boundary. Optional AI job scheduling (`docs/ai-job-scheduling.md`) ranks those peers and controller-local models for unpinned resolve; it does not invent a second playable score.

## Non-Functional Requirements

- **Logging:** Configurable via `LOG_LEVEL` (backend) and `VITE_LOG_LEVEL` (frontend); structured extras for stage/provider/model/import/analysis/arrangement codes and fingerprint prefixes; never log API keys, full prompts, instructions, raw MusicXML/MIDI/video payloads, upload bytes, absolute video paths, catalog override contents, or full analysis/composition reports
- **Error handling:** Domain errors mapped to HTTP 4xx/5xx with sanitized detail; oversized LLM prompts → 422; oversized/hostile imports → 413/415/422; invalid analysis composition/scope → 422; missing LLM/WAV/import deps → 503
- **Security:** Secrets only via environment; CORS for local frontend; no credentials in repo; import rejects DTD/entities, unsafe MXL, and unbounded expansion
- **Testing:** Backend pytest + httpx; frontend Node test runner for utils/store/api; Playwright import and analysis journeys; Docker acceptance includes multipart import. Studio scenarios live in `backend/tests/studio_acceptance/` on the fake bundle. Live models stay `RUN_LLM_SMOKE=1`; the V4 container gate stays `RUN_DOCKER_ACCEPTANCE=1`
